# Retro Rack: notes for Claude Code

Also read `HANDOVER.md`: the history, decisions, reference numbers and ideas list from the chat where this was built.

Retro Rack is a 3D pixel-art pool game: American 8-ball and 9-ball on a 9 ft table, British reds & yellows on a 7 ft table, practice with trick shots, a CPU opponent with four skill levels, same-device play, and online 1v1 through a small Cloudflare relay. It is hosted on GitHub Pages from this repository.

## Project conventions

- Explain changes in plain language, say what will change on screen, and keep jargon out of summaries.
- UK English and metric units everywhere: in the UI, comments and messages.
- Keep the browser console completely clean: no errors, no warnings, no deprecated APIs.
- Test before pushing (see Testing). Never push something untested to `main`, because pushing to `main` deploys straight to the live site.
- Ask before large redesigns or anything that changes how online play works, since both players need the same version.

## Commands

No installs are needed for the game itself, only Node.

- `node tools/build.js`: rebuild `index.html` after any change in `src/`.
- `node tests/physics.test.js`: run the tests. All must pass before pushing.
- `node tools/find-trick-demos.js`: check the trick-shot demos still work, and find new ones.
- `node tools/make-icons.js`: redraw the app icons (pixel art, no installs). The build inlines `icons/favicon-32.png`.
- Relay, locally: `cd relay && npm install && npx wrangler dev`. Then open `index.html?relay=ws://127.0.0.1:8787` in two separate browser windows to play yourself online.

## Deployment (all automatic on push to `main`)

- **GitHub Pages** serves the repository root (`index.html`, `config.js`) at https://flopp-r.github.io/retro-rack/ within a minute or two. Browsers cache; tell the owner to press Ctrl+F5 after an update.
- **Cloudflare Workers Builds** watches the same repository with root directory `relay`, and runs `npx wrangler deploy` when anything changes. The Worker must stay named `retro-rack-relay`, matching `relay/wrangler.jsonc`.
- Both run on free plans. Keep relay changes cheap: the WebSocket Hibernation API, no polling, no per-message storage writes.

## Architecture

### Physics (`src/core.js`)
- Units are metres, kilograms and seconds. The time step is 1 ms.
- Balls carry position, velocity and a full 3D angular velocity. The model covers:
  - sliding versus rolling friction against the cloth, and spin decay about the vertical axis;
  - ball-to-ball collisions with speed-dependent friction, which produces throw;
  - cushions whose nose sits above the ball's centre, so side spin changes the rebound angle;
  - squirt from side spin.
- Collisions rewind to the exact moment of contact before resolving.
- Tables are data in `SPECS` (`us9`, `uk7`). Call `setTable(key)` to switch. Pockets have angled jaws, rounded (filleted) on the UK table.

### Determinism: critical for online play
Both browsers simulate every shot and must get bit-identical results, so keep these rules:
- Inside `step()` and the functions it calls, use only `+ - * /`, `Math.sqrt`, `abs`, `min`, `max`, `round` and `sign`. Engines may differ in the last bit for `Math.exp`, `sin`, `cos`, `pow`, `atan2` and similar. Use `detExp()` for exponentials.
- Table geometry is snapped to 1e-9 m with `q9()`, so trig differences during setup vanish.
- `strike()` does use trig, so the shooter sends the resulting velocities and the receiver checks them against its own calculation.
- No `Math.random` in the physics. Racks are generated by the host and sent as exact numbers.
- The tests check determinism; keep that test passing.

### Rules
`judge(game, rec, before, after, player)` decides fouls and wins from what happened during a shot (`rec`: first ball hit, cushions hit, balls potted). `nextGame()` applies the result. Modes:
- `8ball`: WPA-style, without called pockets.
- `9ball`.
- `uk8`: British pub rules. Two visits after a foul, a free ball on the first visit, ball in hand behind the baulk line after an in-off.
- `practice`.

The CPU (`planBot`) is a generator, so its search can be spread across frames. It simulates candidate shots with the same physics and scores the outcomes. Its strength levels are in `DIFF`.

### Browser (`src/game.js`)
- **Rendering:** the scene is drawn at low resolution into a render target. A post-processing shader then adds depth-based outlines, a vignette, Bayer dithering and colour quantisation. Lights use three.js physical units; the legacy lighting mode is gone.
- **States:** `menu`, `lobby`, `aim`, `stroke`, `moving`, `remote` (waiting for the online opponent), `botThink`, `botAim` and `over`.
- **Replay:** stores the table before the last shot plus the cue ball's initial velocities, then re-simulates.
- **Trick shots:** the `TRICKS` list sits near the top of `game.js`. Saved layouts are kept in localStorage.
- **Settings:** `S` in localStorage (`retroRack.settings`). `S.volume` (0 to 1, 0.75 being the original loudness) replaced the old `S.sound` switch, which is carried over on load. `S.vibrate` buzzes for the local shooter's pots and fouls, only on touch devices with `navigator.vibrate`. The fullscreen buttons and the sideways hint are set up in the "phone and screen comforts" section of `game.js`.
- **Menu screens:** `#menu` holds a stack of `.mScreen` sections (home, single, multi, game, setup, practice, online). `menuGo()`, `menuBack()` and `menuReset()` move between them with slide animations; `NAV` keeps the stack. While away from home one history entry is kept armed, so a phone's back gesture goes back a screen, cancels the waiting room, or opens Pause in a game, instead of leaving the page. `menuTable()` switches the table behind the menu to match the choice. `M.last` holds the setup for "Play again". Card pictures are drawn by `drawArt()`.
- **Phone layout:** the media queries in `shell.html` switch to it on narrow (760 px or less) or short (500 px or less) screens, so phones on their side get it too. `hudVars()` keeps two CSS variables current: `--bb` (bottom of the scoreboard) and `--tb` (top of the bottom-left button grid, which the practice buttons and the chat menu stack above). Check HUD changes at phone-landscape sizes such as 762×341 and 915×412 as well as on a computer.
- **Markers:** `markedBalls()` picks the balls the shooter is on (their group, then the black; the lowest ball in 9-ball; nothing on the break, an open table or in practice). `updateMarkers()` draws a camera-facing halo (a sprite) round each one, only while a local human is aiming. Display only: nothing is sent online. Switch: `S.markers`.

### Online play
- The browser in each seat runs the full game; the relay only forwards messages.
- **Messages sent by the relay:** `welcome` (with the seat), `peer` (on or off) and `full`.
- **Messages between players:** `hello` (name, whether a game is under way, and `v`, the version), `setup` (the host's rack, mode, aim guide and match length), `state` (a full snapshot for resyncs), `aim` (live cue preview), `shot` (shot number, inputs, initial velocities and cue placement), `sync` (the shooter's table after the shot), `chat` (a preset index only), `concede`, `rerackOffer`, `rerackYes`, `rerackNo`, `again` and `bye`.
- **The input-only check:** the receiver validates cue ball placement and recomputes the strike itself. The shooter's `sync` is then a cross-check; a mismatch shows a warning and adopts the shooter's table.
- **Reconnecting:** uses a per-tab client id kept in sessionStorage, so a reload keeps the seat. A duplicated tab copies sessionStorage, so each open page marks the id as in use (`rr.live`, cleared on `pagehide`); a copy that finds the mark picks a fresh id.
- **Versions:** `tools/build.js` stamps `BUILD` in `game.js` with a fingerprint of the game code, shown at the bottom of the menu. `hello` carries it. Before a game starts, a mismatch (or a peer sending no version, i.e. older than this check) stops the game starting and tells the players to reload. Mid-game it only warns, since the `sync` cross-check keeps the tables matched.
- **Installable app:** `game.js` adds the manifest link and registers `sw.js` only on http(s), so a copy opened from disk stays quiet. Service workers don't run from `file://`, so test the app parts through a local web server.
- **Relay (`relay/src/index.js`):** a `Room` Durable Object per room code (seats, reconnects, listing), plus a single `Lobby` Durable Object for the open-rooms list that menus watch over a WebSocket. Migrations are `v1` (Room) and `v2` (Lobby). Adding a Durable Object class needs a **new** migration tag; never edit existing ones.
- **Compatibility:** changing the message format means both players need the new version. Keep old fields working where possible.

## Testing

1. Run `node tests/physics.test.js`; it must report 0 failed.
2. For gameplay or UI changes, open `index.html` in a browser and try the change, watching the console.
3. For anything online, run the relay locally and use two separate browser windows. Check that the tables stay identical after shots, and that a reload mid-game rejoins.
