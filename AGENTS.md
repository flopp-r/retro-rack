# Retro Rack: guide for AI assistants and developers

This is the main guide for anyone, person or AI, who changes this project. Claude Code reads it through `CLAUDE.md`; other AI coding tools (OpenAI Codex, Cursor, GitHub Copilot and others) read `AGENTS.md` directly. A chat AI that can't open the repository can be given `CONTEXT.md` instead: this guide, the other notes, a map of the code and the full source in one file (`CONTEXT-SHORT.md` is the same without the source).

## Start here

**What it is.** Retro Rack is a 3D pixel-art pool game: American 8-ball and 9-ball on a 9 ft table, British reds & yellows on a 7 ft table, practice with trick shots, a CPU opponent with four skill levels, a career mode (a tour of knockout tournaments against named computer players, from the pub to the national tour), a locker of looks (cloths, cues and floating gloves, bought or won in cases), same-device play, and online 1v1 through a small Cloudflare relay. It is one self-contained web page, hosted on GitHub Pages from this repository, and installable as an app. Live: https://flopp-r.github.io/retro-rack/

**Read in this order**
1. This file: how it works, the rules, and how to test and ship a change.
2. `HANDOVER.md`: why things are the way they are, reference numbers (physics, tables, lighting) and a dated list of every change shipped.
3. `README.md`: how the owner set it up, and what players see.
4. The code: `src/core.js` (physics, rules, CPU), `src/career.js` (the career tour), `src/looks.js` (cases and the locker), then `src/game.js` (everything in the browser). Both are split into sections marked `// ------ name`; the map in `CONTEXT.md` lists them with line numbers.

**Rules that must never be broken**
1. **Identical physics in both browsers.** Online, each browser simulates every shot and the results must match to the last bit. See "Determinism" below before touching anything `step()` calls.
2. **`index.html` is built output.** Edit `src/`, then run `node tools/build.js`, and commit both.
3. **A clean console:** no errors, warnings or deprecated APIs.
4. **`main` is live.** Pushing to `main` deploys the site (and the relay, if `relay/` changed). Work on a branch and test first.
5. **Online changes need both players on the same version.** Ask the owner before changing online messages or behaviour, and keep old fields working where possible.
6. **The repository is public.** Never commit personal details, passwords, tokens or keys. The relay address in `config.js` is fine; it has to be public.

## Project conventions

- Explain changes in plain language, say what will change on screen, and keep jargon out of summaries.
- UK English and metric units everywhere: in the UI, comments and messages.
- Ask before large redesigns, as well as before anything that changes online play (rule 5 above).
- Every menu screen must fit a phone held sideways (762×341) without scrolling. The locker's inventory and shop are long lists that scroll inside the panel (`.lockList`); the screen itself still fits.
- Code style: match the file you're in. Compact, mostly one statement per idea, comments only where the reason isn't obvious. No build step beyond `tools/build.js`, and no frameworks or npm packages in the game.

## Commands

No installs are needed for the game itself, only Node.

- `node tools/build.js`: rebuild `index.html` after any change in `src/`. It also remakes `CONTEXT.md` and `CONTEXT-SHORT.md`, so run it after changing the notes too.
- `node tests/physics.test.js`, `node tests/career.test.js` and `node tests/looks.test.js`: the physics, rules, career and looks tests (`npm test` runs all three). All must pass before pushing.
- `node tools/sim-career.js [names] [frames]`: measure career opponents' strength in their tier's game (all of them, 60 frames each, by default; the 36 opponents at 80 frames take about 40 minutes on 4 cores). `@hard:9ball` and the like measure a CPU level as a yardstick. Put the ratings it prints into `src/career.js`.
- `node tests/browser/run-all.js [words]`: run the browser tests (all of them, or only files whose names contain the words). See Testing.
- `node tools/find-trick-demos.js`: check the trick-shot demos still work, and find new ones.
- `node tools/make-icons.js`: redraw the app icons (pixel art, no installs). The build inlines `icons/favicon-32.png`.
- Relay, locally: `cd relay && npm install && npx wrangler dev`. Then open `index.html?relay=ws://127.0.0.1:8787` in two separate browser windows to play yourself online.

## Deployment (all automatic on push to `main`)

- **GitHub Pages** serves the repository root (`index.html`, `config.js`) at https://flopp-r.github.io/retro-rack/ within a minute or two. Browsers cache; tell the owner to press Ctrl+F5 after an update.
- **Cloudflare Workers Builds** watches the same repository with root directory `relay`, and runs `npx wrangler deploy` when anything changes. The Worker must stay named `retro-rack-relay`, matching `relay/wrangler.jsonc`.
- Both run on free plans. Keep relay changes cheap: the WebSocket Hibernation API, no polling, no per-message storage writes.

## How changes are made

1. Agree the change with the owner first: explain the trade-offs, recommend one, then build what they pick.
2. Work on a branch. Edit `src/` (and the notes), run `node tools/build.js`, run the tests (see Testing), and commit `src/`, `index.html` and the context packs together.
3. Open a pull request into `main`. When the owner says to merge, squash-merge it.
4. GitHub Pages publishes within a minute or two; the "pages build and deployment" run in the repository's Actions confirms it. Read the version from the committed `index.html` (`const BUILD = '…'`), not from memory, and tell the owner, who checks it at the bottom of the menu after pressing Ctrl+F5.
5. On pull requests, the Cloudflare check "Workers Builds: retro-rack-relay" fails at once: it's a preview build, and is unrelated unless `relay/` changed. The production relay deploys from `main` as normal.

## Architecture

### Physics (`src/core.js`)
- Units are metres, kilograms and seconds. The time step is 1 ms.
- Balls carry position, velocity and a full 3D angular velocity. The model covers:
  - sliding versus rolling friction against the cloth, and spin decay about the vertical axis;
  - ball-to-ball collisions with speed-dependent friction, which produces throw;
  - cushions whose nose sits above the ball's centre, so side spin changes the rebound angle;
  - squirt from side spin.
- Collisions rewind to the exact moment of contact before resolving.
- Tables are data in `SPECS` (`us9`, `uk7`). Call `setTable(key)` to switch. Pockets have angled jaws, rounded (filleted) on the UK table.

### Determinism: critical for online play
Both browsers simulate every shot and must get bit-identical results, so keep these rules:
- Inside `step()` and the functions it calls, use only `+ - * /`, `Math.sqrt`, `abs`, `min`, `max`, `round` and `sign`. Engines may differ in the last bit for `Math.exp`, `sin`, `cos`, `pow`, `atan2` and similar. Use `detExp()` for exponentials.
- Table geometry is snapped to 1e-9 m with `q9()`, so trig differences during setup vanish.
- `strike()` does use trig, so the shooter sends the resulting velocities and the receiver checks them against its own calculation.
- No `Math.random` in the physics. Racks are generated by the host and sent as exact numbers.
- The tests check determinism; keep that test passing.

### Rules
`judge(game, rec, before, after, player)` decides fouls and wins from what happened during a shot (`rec`: first ball hit, cushions hit, balls potted). `nextGame()` applies the result. Modes:
- `8ball`: WPA-style, without called pockets.
- `9ball`.
- `uk8`: British pub rules. Two visits after a foul, a free ball on the first visit, ball in hand behind the baulk line after an in-off. Optional `game.oneVisitOnBlack`: a player on the black only ever gets one visit; `nextGame()` needs the table after the shot (its fourth argument) to apply it.
- `practice`.

The CPU (`planBot`) is a generator, so its search can be spread across frames. It simulates candidate shots with the same physics and scores the outcomes. Its strength levels are in `DIFF` (each field is explained above it); `planBot` also takes a profile object with the same fields, which is how career opponents get their personalities (`long` adds aim error on long pots).

### Career (`src/career.js`, and the career section of `game.js`)
- **The tour:** `TIERS` hold events: the pub circuit (reds & yellows, 7 ft), the club and hall circuits (8-ball, 9 ft) and the national tour (9-ball, 9 ft), three events each, every event with a `sign` for the neon sign. Each event is an 8-player knockout (you and 7 of `field`), with `races` (frames to win the quarter-final, semi-final and final) and `prize` (money for going out in each round, then for winning). Winning an event opens the next (`unlocked()`); winning the tier's last event completes the tier.
- **Opponents:** `OPPONENTS` gives each a name, a pixel portrait (`look`, drawn by `portrait()` in `game.js` from the `SPRITES` styles), a blurb, a base CPU level plus overrides (`cfg`), optional `nerves` (execution error multiplier on the final ball, see `onFinalBall()`), and a `rating` measured with `tools/sim-career.js` (Medium CPU = 1500). Ratings settle computer-v-computer matches in a draw (`simMatch()`, Elo-style, always within one game) and, through `strength()`, give the strength stars (9-ball ratings are stretched to compare with 8-ball, using the Hard CPU as the yardstick; see `GAME_SCALE`).
- **Draws and results** are seeded (`rng()`), so reloading never changes them. `enterEvent()` makes the draw (top two seeds in opposite halves), `recordMatch()` records your match, plays out the rest of the round, pays prizes and finishes the event; `withdraw()` counts as losing the current match. `validate()` checks a saved or imported career and returns a clean copy.
- **Money and the shop:** the career only counts what it has won (`earned`); the prize money itself goes into the device's locker (see Looks), by `careerPaid()` in `game.js`, with the case an event win brings. `SHOP` lists the cloths and cues sold outright (cue designs colour the shaft, joint, forearm, wrap, butt and inlay; `HOUSE_CUE` is the free one). Saves from before the locker kept `money` and `bought`; `validate()` keeps them and `game.js` moves them into the locker once.
- **In the browser:** the career lives in `CAR.data` (localStorage `retroRack.career`). Screens `cnew` (new career: name, look, aim guide fixed for the career), `career` (the hub: one tier at a time, chosen with tabs; `careerTier()` picks the one to show; its Locker button opens the locker) and `cevent` (the draw and your next opponent), drawn by `careerMenus()`; the footer's `#bCareer` and `#bWithdraw` buttons act on them. Save to file / Load from file export and import the career as JSON, with the locker inside (`locker`); loading merges it in without taking anything away.
- **Venues:** `VENUES` in `game.js` dress the room (carpet, walls, skirting, the neon sign's colours) for each tier; `setVenue(key, sign)` swaps them. A career match, and the event screen behind the menu, use the event's tier and sign; everything else uses `home`.
- **Cues:** the cue's parts take a design's colours (`applyCue()`), and a pattern drawn round the forearm (`cuePattern()`) with its effect (`cueFx()`); `cueFor(player)` decides whose cue is at the table: yours, a career opponent's own (`cue` in `OPPONENTS`), the house cue for the CPU, and online the other player's. Gloves follow the same rules (`gloveFor()`, `glove` in `OPPONENTS`; the CPU otherwise has none).

### Looks and the locker (`src/looks.js`, and the locker and gloves sections of `game.js`)
- **The catalogue:** `CASE_ITEMS` holds 60 looks that come only in cases: 14 patterned cloths (`pat`, drawn by `drawPattern()` onto the bed as a texture, metre for metre), 20 cues (`pat` and `pc` for a forearm pattern, `fx` glow, neon or rainbow) and 26 gloves (`style`, one of the glove types in `STYLE` in `game.js`: sport, driver, tactical, moto, fingerless and hand wraps, plus three novelties, boxing, robot claw and skeleton; and `fx` glow, flicker or ghost). Each has a rarity (`RARITY`: common, rare, epic, legendary and mythic, with the price a duplicate sells for). The legendary and mythic ones are painted pixel by pixel from noise (`makeNoise()`, `fbm()` and `paint()`, in the collection effects section): the cloths by `clothGalaxy()`, `clothSynth()`, `clothAurora()` and `clothMagma()` (at half the bed's usual resolution, and the last four kept in `CLOTH_CACHE`, so they're quick), the cues by `cuePaint()` (`pat` holo, tubes, swirl and plasma), the gloves by `gloveTex()` (gold leaf, fire, smoke, molten crust and holographic bands, wrapped round each finger and laid across the hand; only legendary and mythic gloves have one).
- **Mythics** (red, two of each kind) move: the cloths Aurora (`anim: 'flow'`, the texture drifts, `clothFx()`) and Magma (`anim: 'pulse'`, its cracks glow through an emissive map, `clothGlow`), the cues Event horizon (`fx: 'spin'`) and Plasma (`fx: 'plasma'`), whose seamless forearm patterns scroll in `cueFx()`, and the gloves Molten and Prism (`fx: 'molten'`, `'prism'`), whose glow (Molten) or bands (Prism) move in `gloveFx()`. Brightness only changes slowly (nothing faster than about 3 times a second), and with reduced motion they hold still. `ALL` is every look by id: the shop's, the cases' and `FREE_GLOVE`. `FREE` lists what everyone owns ('house', 'none', the free glove; the five original cloths are free too).
- **Cases:** `GRADES` (bronze, silver, gold, diamond) give the odds of each rarity, the cost to open one and the price to buy one; legendaries only come in silver and better; mythics come in every grade, very rarely (0.2% in bronze up to 3% in diamond). `roll()` picks the prize (an epic or better is guaranteed within `PITY` = 8 cases), `openCase()` pays, picks and sells a duplicate at once (but a mythic is always one not owned yet, until all six are), `reelItems()` fills the reel with items drawn from the same odds. `buyCase()` and `buyLook()` spend money.
- **Earning:** `cpuFrameWon()` (a frame won against the computer pays `CPU_PAY`, £15 on Easy up to £150 on Expert, and moves the level's meter on; `METER` = 1, so every frame won earns a case of the level's grade), `careerFrameWon()` (a case of the tier's grade for every career frame won, no pay), `eventWon()` (`EVENT_CASES` = 2 cases of the tier's grade, a championship two of the grade above, four of the best at the top) and `onlineWon()` (the day's first online win, once per local date: £100 and two gold cases). Practice and same-device games earn nothing. `frameEarn()` in `game.js` calls them when a frame ends; `EARN` holds the result for the result screen.
- **Collections:** the case looks of one rarity and one kind make a collection (`COLLECTIONS`, keyed `'rarity:kind'`, 15 in all; `colItems()` lists one's looks): the common cloths, the mythic gloves and so on. Each pays money and cases when complete (`KIND_REWARD`: common £150 and a silver case, up to mythic £5,000 and three diamond cases). All three of a rarity make its set (`SETS`), which pays far more and adds the rarity's effect (`EFFECTS`): common £1,000, three gold cases and the chalk trail; rare £2,500, three diamond cases, gold rails; epic £5,000, five diamond cases, pot sparks; legendary £12,000, eight diamond cases, your name in neon; mythic £30,000, twelve diamond cases, the cosmic cue ball. All fifteen (`GRAND`): £50,000 and the starfield room. `claimCollections()` pays whatever is due, each only once (collections, then sets, then 'all'); `openCase()` calls it and returns what it completed as `done`, and `claimDue()` in `game.js` calls it after loading a career file and at start-up. `effects()` lists the effects earned. Dev mode's test locker counts every reward as already paid.
- **The locker** (localStorage `retroRack.locker`, `LOCK` in `game.js`): `money`, `owned`, `cases`, `meter`, `pity`, `daily`, `opened`, `claimed` (the collections paid); `validateLocker()` cleans a saved one and `mergeLocker()` brings in one from a career file. Every change goes through `lockerEdit()`, which reads the stored copy, changes it and writes it straight back, so two open pages don't undo each other's changes; a `storage` listener shows changes made in another page. A new locker starts with £40 and a silver case, so everyone can try one. On first load the locker takes in looks from older versions (`S.owned`) and a career's unspent money.
- **The locker screen** (`locker`, from the home screen's Locker card or the career hub), drawn by `renderLocker()`, with three tabs:
  - **Cases:** each grade's odds, Open and Buy, the meters and the guarantee.
  - **Inventory:** one long list (`invRow()`) of everything owned, rarest first (`lookRank()`, `lookSort()`: mythic down to common, then the shop's looks, then the free ones), under a heading per rarity; tapping one puts it in use. Above it, the collection rewards earned, each with an On/Off switch (`S.fxOff`).
  - **Shop:** the looks for sale outright in a first row, then a section per rarity, rarest first: its set (how many of its three collections are done, and the set's reward), then its cloth, cue and glove collections, each with how many you have, its reward and its looks (`colTile()`: owned tiles bright with a tick, the rest dimmed); a last line for all fifteen.
  - `lookTap()` handles a tap anywhere: an owned look goes into use; one you don't own (or a shop look you don't buy) is marked to try on (`LOCKV.try`, by kind, dashed outline). The lists keep their scroll position when they redraw.
  - Item pictures are pixel art: `clothImg()`, `cueIcon()`, `gloveImg()`, `caseImg()`. Settings has a picker for each kind (`lookPicker()`).
- **Preview** (`#bPreview` in the footer of the inventory and the shop, `startPreview()`, `endPreview()`): the menu steps aside and the camera (`cam.mode` `'show'`) swings slowly round the side of the cue, lined up on the nearest ball, showing your cloth, cue and gloves with any look marked to try in its place (`PREV.looks`; `cueFor()`, `gloveFor()` and `setCloth()` use them while `PREV.on`). Nothing is saved. A tap anywhere (`#preview`), Esc or the back gesture ends it; with reduced motion the camera holds still.
- **The reel** (`#reel`, `showReel()`): the locker pays and picks the prize first, then a strip of the case's items glides past a marker and stops on it; the other items come from the case's odds and the stopping point within the prize's tile is random, so it never fakes a near miss. Each tile is in its rarity's colour (`reelTile()`), fading from a dark shade at the top to nearly the full colour at the bottom. It takes 7 seconds to stop, slowing to a long crawl. Tapping the reel skips to the end; with reduced motion there's no spin. A case that completes a collection, a set or all fifteen says so under the prize (`doneTxt()`). The reel fills most of the screen (tiles 40% of its height, at most 22% of its width) over a dim that leaves the room barely visible.
- **Collection effects** (the collection effects section of `game.js`): `fxOn(k)` is true when the reward is earned and not switched off; `applyFx()` puts them in place after any change. The chalk trail (`TRAIL`, an instanced mesh of dots laid every 1.2 cm along the cue ball's path, shrinking away), gold rails (`railMat` takes `goldTex()` instead of the wood), pot sparks (`sparkAt()`, from the pocket in the ball's colour; off with reduced motion), your name on the home neon sign (`signText()`: the career's name, else the online name), the cosmic cue ball (`cosmicTex()`, pale and bright, with gold spin dots) and the starfield room (`starTex()` on the walls at home). `tableFx()` moves the trail and sparks each frame. Display only, and only on your own screen: nothing is sent online.
- **The show behind the reel** (`#reelFx`, `fxStart()`, `fxFrame()`, drawn at a quarter of the screen's resolution and scaled up): faint stripes while it spins; when it stops, stripes in the prize's rarity colour and its own colour bounce round the screen, more and faster the rarer it is, with sparkles from epic, turning rays from legendary, and for a mythic shifting colours, rings, confetti, a shake and a bigger fanfare (`sfx('fanfare', tier)`). It stops when the reel closes; with reduced motion it's drawn once, still.
- **Gloves** (the gloves section of `game.js`): the one-piece hands are the owner's own procedural model, "Retro Rack hands", built in: low-poly and flat-shaded (the materials use `flatShading`; the geometry has no shared corners), one mesh per hand on a skeleton of 17 bones (`GH_BONES`: the arm, the wrist, three for each finger and three for the thumb). In the model's frame the fingers point along -z and the back of the hand faces +y; `GH_FINGERS` and `GH_THUMB` give each knuckle, width and section lengths for a right hand, and a left hand is a true mirror (`ghMake()` flips x and turns each face back round), so the poses work on both. `ghTris()` lofts rings of corners (`ghRing()`, `ghLoft()`, small boxes from `ghBlock()`) into the cuff (darker inside), the wrist and palm, four six-sided fingers and the thumb, then the type's extras from `STYLE`: a wrist strap, a back panel, a knuckle strip or a raised guard, finger pads, nails where the fingers are bare. Each triangle has a part (slot) that `ghMat()` turns into one of the glove's eight materials (`GLOVE_KEYS`: the back in the main colour, the palm side a little lighter, skin past a fingerless glove's first joint and on all of a wrap's fingers, trims toned towards the main colour by `TONE`); a textured glove's picture covers the back, palm, panel and trims alike. `ghGeo()` makes each type's mesh once per side (`HAND_GEO`, 700 to 770 triangles in four to six groups, one per material used); `ghHand()` puts one on its skeleton in a pose from `GH_POSES` (grip, bridge, and the reactions fist, thumb and open). A pose with an `anchor` says where the cue's middle line passes through the hand, and `ghAttach()` places the hand so the cue runs there: the grip on the cue's butt (a child of the cue, so it strokes with it, thumb towards the tip), and the bridge on the cloth behind the cue ball, kept flat (`level`), its anchor `restHeight` above the cloth; when the cue's line is higher than that (top spin), `updateGloves()` tips the hand up on its fingertips rather than lifting it off the cloth. The boxing glove is one faceted mitt (`boxingGeo()`, the cue resting on its thumb beside it); the robot claw and the skeleton keep their jointed parts (`partsHand()`, with `FINGER`, `THUMB` and `HAND_POSE`, in an older frame with the fingers along +x, which `handBuild()` also turns the one-piece hands into for the reactions). `gloveBuild()` makes the grip, the bridge and the reaction hand. `cheer()` plays a reaction after a shot (a thumbs-up for a pot, a shrug for a foul, a fist pump for winning the frame), off with reduced motion and during replays. A fingertip of the bridge drums while you line up. The cue hand hides when the camera is within 0.3 m of it. Display only: nothing here affects the physics.
- **Career matches** are normal CPU games: `careerPlay()` puts the menu's own choices (`M`) aside in `CAR.stash`, sets `M` from the event, and calls `startGame(false, false, resume)`, where `resume` carries the match score, who breaks and a frame in progress. `CAR.on` is true for the match: `saveM()` and Play again leave the menu's choices alone, the scoreboard and messages use the opponent's name (`botName()`), and Pause has no aim guide choice and no re-rack. `careerSave()` stores the table (`snapshot()`) after every shot, so a match resumes exactly; `careerFrameOver()` records a finished frame and, when the match is won or lost, `recordMatch()`. `careerLeave()` (from `toMenu()`) puts `M` back.

### Browser (`src/game.js`)
- **Rendering:** the scene is drawn at low resolution into a render target. A post-processing shader then adds depth-based outlines, a vignette, Bayer dithering and colour quantisation. Lights use three.js physical units; the legacy lighting mode is gone.
- **States:** `menu`, `lobby`, `aim`, `set` (Shoot pressed, the aim held while the shot camera swings in), `stroke`, `moving`, `remote` (waiting for the online opponent), `botThink`, `botAim` and `over`.
- **Replay:** stores the table before the last shot plus the cue ball's initial velocities, then re-simulates.
- **Trick shots:** the `TRICKS` list sits near the top of `game.js`. Saved layouts are kept in localStorage. In "Edit table" mode (`EDIT`), "Add balls" opens a picker (`renderBallPick()`, `toggleBall()`) to put balls on the table or take them off; it closes when Pause opens.
- **Settings:** `S` in localStorage (`retroRack.settings`). The panel (`#pause`, also opened from the menus' cog) is four sections (Game, Looks, Display, Sound and touch) in two CSS columns (`.sGrid`) where there's room, one on phones; it opens scrolled to the top, sits above the game's messages, and a click outside it closes it (only if the press started outside too). The default graphics are the sharpest (`S.pixel` 1, `S.levels` 256); `S.gfx` = 2 marks settings that have had that default applied, so saved settings without it get it once. Pixel size Max (`S.pixel` 0) draws one game pixel per real screen pixel (`screenDpr()`: the device pixel ratio, at most 3), so a screen scaled above 100% or a phone gets finer detail than 1×, and at 100% it's the same as 1×; `watchDpr()` redraws when the window moves to another screen or the page is zoomed, and `pixNote()` says what Max gives on this screen. `S.cloth`, `S.cue` and `S.glove` are the looks in use ('none' for no gloves); `S.fxOff` lists the collection effects switched off; what's owned is in the locker (`owns()` checks). `S.spinOpen` (see Spin and fine aim). `S.volume` (0 to 1, 0.75 being the original loudness) replaced the old `S.sound` switch, which is carried over on load. `S.vibrate` buzzes for the local shooter's pots and fouls, only on touch devices with `navigator.vibrate`. The fullscreen buttons and the sideways hint are set up in the "phone and screen comforts" section of `game.js`. In the menus, Settings and Fullscreen are pixel icons in the top-right corner (`#menuIcons`, drawn by `setIcon()` from `ICONS`), and the footer hides when a screen has no main button; in a game they stay in the HUD.
- **Dev mode** (for the owner, to try every look): typing the dev word as the name on the Online screen switches it on or off (`isDevWord()`, `setDev()`). Only a SHA-256 fingerprint of `'retroRack:' + word` is in the code (`DEVW.print`), because the repository is public; never write the word into the repository. While it's on (`DEV`, localStorage `retroRack.dev`), `lockKey()` points the locker at a separate test locker (`retroRack.lockerDev`, made by `devLocker()`: every look, £100,000 and 50 of each case), Settings shows a Dev mode row (Switch off, and "Next case mythic": `DEV_MYTHIC`, which makes the next case opened give a mythic through `openCase()`'s `force`, then switches itself off) and the version line says DEV; switching off brings the real locker back and `checkLooks()` takes off anything not really owned. Career prize money earned meanwhile goes into the test locker.
- **Browser storage:** localStorage keys `retroRack.settings` (`S`), `retroRack.menu` (`M`, the menu choices and `M.last`), `retroRack.name` (online name), `retroRack.layouts` (saved trick-shot layouts), `retroRack.rotateHint` (the sideways hint dismissed) `retroRack.rejoin` (see Online play), `retroRack.career` (see Career), `retroRack.locker` (see Looks), and `retroRack.dev` and `retroRack.lockerDev` (dev mode). sessionStorage, per tab: `rr.cid` (online client id) and `rr.live`. Wrap every access in try/catch: storage can be missing or blocked.
- **Menu screens:** `#menu` holds a stack of `.mScreen` sections (home, single, multi, game, setup, practice, online, locker, and the career's cnew, career and cevent). `menuGo()`, `menuBack()` and `menuReset()` move between them; `menuSlide()` makes the whole panel glide across the screen (a copy of the old panel slides off one side as the real one arrives from the other; scope any `.mScreen` lookups to `#menuPanel` so the copy is left alone). `NAV` keeps the stack. While away from home one history entry is kept armed, so a phone's back gesture goes back a screen, cancels the waiting room, or opens Pause in a game, instead of leaving the page. `menuTable()` switches the table behind the menu to match the choice. `M.last` holds the setup for "Play again". Card pictures are drawn by `drawArt()`: arcade-style people sprites (`SPRITES`) and pixel balls. Every menu screen must fit a phone on its side (762×341) without scrolling. The shared styles `.row`, `.lbl`, `.seg`, `.note`, `.swatches` and `.actions` are also used by Settings and the overlays, so keep them when changing the menu CSS.
- **Phone layout:** the media queries in `shell.html` switch to it on narrow (760 px or less) or short (500 px or less) screens, so phones on their side get it too. `hudVars()` keeps four CSS variables current: `--bb` (bottom of the scoreboard), `--tb` (top of the bottom-left button grid, which the practice buttons and the chat menu stack above), and `--lw` and `--sw` (the right edge of the left-hand buttons or the trick panel, and the width of the spin panel, so the ball picker can sit between them on a phone on its side). Check HUD changes at phone-landscape sizes such as 762×341 and 915×412 as well as on a computer. In the phone layout the game's buttons (`.ib`: the left-hand tools, the practice and trick-shot buttons, the aim arrows, the replay bar) are 34 px squares showing a pixel icon from `ICONS` (`setIcon()`), their words hidden; on a computer the words show and the icons hide. `setLab()` changes a button's words, icon and `aria-label` together. A long press on one (`LP`, not the aim arrows, which turn while held) shows its name in `#ibTip` and swallows the click. Shoot keeps its word. `phoneUI` is the same media query in script.
- **Spin and fine aim:** the small ball beside the power bar (`#bSpin`, drawn by `drawMini()`) shows where the tip will strike and shows or hides the spin diagram (`#shot.noSpin`, `applySpinOpen()`): `S.spinOpen`, unset until first tapped, so phones start with it hidden and computers with it shown. Aim: ←/→ or the arrows turn `AIM_STEP` = 0.05° a press (Ctrl + ←/→ `AIM_FINE` = 0.01°; Ctrl with A or D is left to the browser); a held arrow button turns from 0.5°/s, doubling every 0.4 s up to 40°/s; sliding along the aim readout (`#aimTxt`, `jog`) turns `JOG` = 0.0025° per screen pixel, its tick marks moving with the aim.
- **Controls panel** (`#help`): single key presses go through `keyAct()`, which the panel's keys (`kbd.tap`, `tapKey()`) call too, so tapping a key does what pressing it does; power keys step by 0.025 per tap and Q/E turn the camera about 25°. Keys matching `KEY_STAY` (aim, power, spin) leave the panel open; the rest close it first. Shift, Ctrl and Alt aren't tappable.
- **Markers:** `markedBalls()` picks the balls the shooter is on (their group, then the black; the lowest ball in 9-ball; nothing on the break, an open table or in practice). `updateMarkers()` draws a camera-facing halo (a sprite) round each one, only while a local human is aiming. Display only: nothing is sent online. Switch: `S.markers`.
- **Shot camera:** a local human's Shoot (`shoot()`: the Shoot button, Space or Enter, and the trick shots' Show me) holds the aim for `SET_T` = 0.9 s (state `set`) while the camera's `'shot'` mode glides in, eased all the way (`cam.shot.from`), to the shooter's eyes: standing over the cue, about 40 cm up and 60 cm back, looking down the line from where the shot was played; then `beginStroke()` plays the stroke as usual (online, that's when the shot is sent, so both screens stay in step). `RISE_WAIT` = 0.3 s after the strike (state `moving`), the view rises over `RISE_T` = 1.2 s, eased, to `cam.high()`: above the long side you're nearer, `HIGH_PITCH` = 60° down, far enough back that the table and rails fill about 90% of the screen (or to `cam.top()` if you shot from the overhead view); meanwhile the spin and power panel and the buttons on the left fade (`.away` on `#shot`, `#tools` and `#practice`; they still work). Once the balls stop, `cam.shotOver()` puts back the view you had. Moving the camera mid-shot (a drag, Cue view or Overhead) keeps your view instead. Not for the computer's or an online opponent's shots; with reduced motion or the Settings switch off (`S.shotCam`, on by default) the stroke starts at once with no swing. If the shot can't go after the hold (the opponent's connection dropped, say), the view goes back. Display only: nothing new is sent online.

### Online play
- The browser in each seat runs the full game; the relay only forwards messages.
- **Messages sent by the relay:** `welcome` (with the seat), `peer` (on or off) and `full`.
- **Messages between players:** `hello` (name, whether a game is under way, `v` the version, and the player's `cue`, `cloth` and `glove`), `look` (a player changed their cue, cloth or gloves mid-game), `setup` (the host's rack, mode, aim guide, match length and `blackOne`, the "one visit on the black" rule), `state` (a full snapshot for resyncs), `aim` (live cue preview), `shot` (shot number, inputs, initial velocities and cue placement), `sync` (the shooter's table after the shot), `chat` (a preset index only), `concede`, `rerackOffer`, `rerackYes`, `rerackNo`, `again` and `bye`.
- **Looks:** each player's cue and gloves are shown on both screens, and the table wears the host's (seat 0's) cloth: `takeLooks()` reads them from `hello` and `look`, accepting only known design ids (anything else becomes the house cue, no gloves, or the receiver's own cloth). `NET.cloth`, `NET.peerCue` and `NET.peerGlove` are cleared on leaving. Display only: nothing here affects the physics.
- **The input-only check:** the receiver validates cue ball placement and recomputes the strike itself. The shooter's `sync` is then a cross-check; a mismatch shows a warning and adopts the shooter's table.
- **Reconnecting:** uses a per-tab client id kept in sessionStorage, so a reload keeps the seat. A duplicated tab copies sessionStorage, so each open page marks the id as in use (`rr.live`, cleared on `pagehide`); a copy that finds the mark picks a fresh id.
- **Rejoin:** whenever an online game starts, is restored or a shot ends, the page saves the room code, its client id, the opponent's name and the mode in localStorage (`retroRack.rejoin`: a list, one entry per client id, kept 3 hours). The home screen's Rejoin button (`updateRejoin()`) puts that id back into sessionStorage and joins the room, so the relay returns the same seat and an opponent whose page is still open sends the table (`state`). If neither page is still open, a fresh frame starts. Quit, Menu on the result screen, Cancel in the waiting room, a full room and the opponent's `bye` (leaving on purpose) forget the entry. Each page in a room holds a Web Lock named `retroRack.seat.<cid>` (`holdSeat()`, freed by `leaveOnline()` or by closing the page), and the button skips entries whose lock is held, so a second tab on the same device never takes over a seat that's still open.
- **Versions:** `tools/build.js` stamps `BUILD` in `game.js` with a fingerprint of the game code, shown at the bottom of the menu. `hello` carries it. Before a game starts, a mismatch (or a peer sending no version, i.e. older than this check) stops the game starting and tells the players to reload. Mid-game it only warns, since the `sync` cross-check keeps the tables matched.
- **Installable app:** `game.js` adds the manifest link and registers `sw.js` only on http(s), so a copy opened from disk stays quiet. Service workers don't run from `file://`, so test the app parts through a local web server.
- **Relay (`relay/src/index.js`):** a `Room` Durable Object per room code (seats, reconnects, listing), plus a single `Lobby` Durable Object for the open-rooms list that menus watch over a WebSocket. Migrations are `v1` (Room) and `v2` (Lobby). Adding a Durable Object class needs a **new** migration tag; never edit existing ones.
- **Compatibility:** changing the message format means both players need the new version. Keep old fields working where possible.

## Testing

1. **Physics, rules, career and looks:** `node tests/physics.test.js`, `node tests/career.test.js` and `node tests/looks.test.js` must each report 0 failed. It covers bit-identical results, pockets on both tables, breaks, the rules of every mode, the trick-shot demos, and that `CONTEXT.md` and `CONTEXT-SHORT.md` match the code and notes (if not, run the build).
2. **Browser tests:** `node tests/browser/run-all.js` builds the game, serves three copies of it locally like GitHub Pages (the current build, an old build from before the version check, and the current build with a different version number), starts the relay locally with Wrangler, then runs every `*.test.js` in `tests/browser/` in headless Chromium and prints a summary. Each check prints `PASS` or `FAIL`, and each file also fails if anything reaches the browser console.
   - Needs Playwright with Chromium (preinstalled in Claude Code's cloud sessions; elsewhere `npm install --no-save playwright` then `npx playwright install chromium`) and npm, which installs the relay's packages once into a temporary folder. Nothing is written into the repository; screenshots go to the temporary folder, printed at the end.
   - Software rendering is slow: the whole set takes about 12 minutes in a Claude Code cloud session. To keep it so, `lib.js` starts test pages at pixel size 3× and 8 shades rather than the game's sharper defaults, unless a test sets its own settings or opens the page with `?realdefaults` (as the check of the defaults does). For a small change, run the files that cover it, e.g. `node tests/browser/run-all.js menus fit`.
   - The files: `menus` (every menu route, back navigation, Play again), `fit` (every menu screen fits a phone on its side without scrolling), `online` (games through the relay, reload rejoin, duplicated tabs, version mismatches), `rejoin` (the Rejoin button), `comforts` (volume, fullscreen, sideways hint, vibration, pixel size Max at three screen scales; over http), `markers` (the halos on the balls you're on; over http), `phone` (icon squares on a phone and words on a computer, a long press showing a name, the spin diagram's toggle and its kept choice, sliding on the aim readout, the gentle hold, Ctrl + arrow, the Controls panel's tappable keys), `shotcam` (the shot camera: the held aim, then the stroke, the rise to the whole table and the faded buttons, from the overhead view too, your shots only, back to your view, its switch, reduced motion), `hud` (no HUD pieces overlap at phone, tablet and computer sizes), `file` (the page opened from disk), `app` (installable app, offline start, updates), `add-balls-and-black` (Add balls in the trick-shot editor, and "one visit on the black"), `career` (a new career, draws, playing, leaving and resuming a match, winning and losing, money, unlocking, save to file and load, withdrawing, retiring; served over http, like `locker`), `shop` (tier tabs, the shop in the locker, bought looks in Settings and in every game, venues), `looks` (online: each player's cue and gloves and the host's cloth on both screens, the day's first online win), `locker` (old saves moving in, opening a case and the reel, buying, duplicates, two open pages, earning, tiles in their rarity's colour, the show behind the reel for a common and a mythic, and still with reduced motion, Preview with looks tried on (and leaving it by a tap, the back gesture and Esc), the shop's collection rows, completing a collection (the reel's message, the reward paid once, every effect on and its switch), the inventory in rarity order, patterned cloths, gloves and moving mythics at the table, each glove one low-poly piece on its skeleton with the cue hand wrapped round the cue, the robot's parts and steel, a glove's reaction to a foul, dev mode with a stand-in word and its "next case mythic" switch; served over http, because pages opened from disk don't reliably share storage changes).
   - A test that reloads a page, reopens one or uses two pages needs storage to carry over, so it runs over http (`SITE.new`): in the test browser, pages opened from disk don't always share or keep their storage.
   - New features get a new test file, or new checks in the file that fits. Keep test windows small (about 480×360) unless the size is what's being tested.
3. **By eye:** for gameplay or UI changes, open `index.html` in a browser and try the change, watching the console. For anything online, run the relay locally (see Commands) and play yourself in two separate browser windows.
