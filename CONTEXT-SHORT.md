# Retro Rack: guide for AI assistants and developers

This is the main guide for anyone, person or AI, who changes this project. Claude Code reads it through `CLAUDE.md`; other AI coding tools (OpenAI Codex, Cursor, GitHub Copilot and others) read `AGENTS.md` directly. A chat AI that can't open the repository can be given `CONTEXT.md` instead: this guide, the other notes, a map of the code and the full source in one file (`CONTEXT-SHORT.md` is the same without the source).

## Start here

**What it is.** Retro Rack is a 3D pixel-art pool game: American 8-ball and 9-ball on a 9 ft table, British reds & yellows on a 7 ft table, practice with trick shots, a CPU opponent with four skill levels, a career mode (a tour of knockout tournaments against named computer players, from the pub to the national tour), a locker of looks (cloths, cues and floating gloves, bought or won in cases), same-device play, and online 1v1 through a small Cloudflare relay. It is one self-contained web page, hosted on GitHub Pages from this repository, and installable as an app. Live: https://flopp-r.github.io/retro-rack/

**Read in this order**
1. This file: how it works, the rules, and how to test and ship a change.
2. `HANDOVER.md`: why things are the way they are, reference numbers (physics, tables, lighting) and a dated list of every change shipped.
3. `README.md`: how the owner set it up, and what players see.
4. The code: `src/core.js` (physics, rules, CPU), `src/career.js` (the career tour), `src/looks.js` (cases and the locker), then `src/game.js` (everything in the browser). Both are split into sections marked `// ------ name`; the map in `CONTEXT.md` lists them with line numbers.

**Rules that must never be broken**
1. **Identical physics in both browsers.** Online, each browser simulates every shot and the results must match to the last bit. See "Determinism" below before touching anything `step()` calls.
2. **`index.html` is built output.** Edit `src/`, then run `node tools/build.js`, and commit both.
3. **A clean console:** no errors, warnings or deprecated APIs.
4. **`main` is live.** Pushing to `main` deploys the site (and the relay, if `relay/` changed). Work on a branch and test first.
5. **Online changes need both players on the same version.** Ask the owner before changing online messages or behaviour, and keep old fields working where possible.
6. **The repository is public.** Never commit personal details, passwords, tokens or keys. The relay address in `config.js` is fine; it has to be public.

## Project conventions

- Explain changes in plain language, say what will change on screen, and keep jargon out of summaries.

- Ask before large redesigns, as well as before anything that changes online play (rule 5 above).
- Every menu screen must fit a phone held sideways (762×341) without scrolling. The locker's inventory and shop are long lists that scroll inside the panel (`.lockList`); the screen itself still fits.

- **GitHub Pages** serves the repository root (`index.html`, `config.js`) at https://flopp-r.github.io/retro-rack/ within a minute or two. Browsers cache; tell the owner to press Ctrl+F5 after an update.

1. Agree the change with the owner first: explain the trade-offs, recommend one, then build what they pick.
2. Work on a branch. Edit `src/` (and the notes), run `node tools/build.js`, run the tests (see Testing), and commit `src/`, `index.html` and the context packs together.
3. Open a pull request into `main`. When the owner says to merge, squash-merge it.
4. GitHub Pages publishes within a minute or two; the "pages build and deployment" run in the repository's Actions confirms it. ## Architecture

### Physics (`src/core.js`)
- Units are metres, kilograms and seconds. The time step is 1 ms.
- Balls carry position, velocity and a full 3D angular velocity. The model covers:
  - sliding versus rolling friction against the cloth, and spin decay about the vertical axis;
  - ball-to-ball collisions with speed-dependent friction, which produces throw;
  - cushions whose nose sits above the ball's centre, so side spin changes the rebound angle;
  - squirt from side spin.
- Collisions rewind to the exact moment of contact before resolving.
- Tables are data in `SPECS` (`us9`, `uk7`). Call `setTable(key)` to switch. Pockets have angled jaws, rounded (filleted) on the UK table.

### Determinism: critical for online play
Both browsers simulate every shot and must get bit-identical results, so keep these rules:
- Inside `step()` and the functions it calls, use only `+ - * /`, `Math.sqrt`, `abs`, `min`, `max`, `round` and `sign`. Engines may differ in the last bit for `Math.exp`, `sin`, `cos`, `pow`, `atan2` and similar. Use `detExp()` for exponentials.
- Table geometry is snapped to 1e-9 m with `q9()`, so trig differences during setup vanish.
- `strike()` does use trig, so the shooter sends the resulting velocities and the receiver checks them against its own calculation.
- No `Math.random` in the physics. Racks are generated by the host and sent as exact numbers.
- The tests check determinism; keep that test passing.

### Rules
`judge(game, rec, before, after, player)` decides fouls and wins from what happened during a shot (`rec`: first ball hit, cushions hit, balls potted). `nextGame()` applies the result. Modes:
- `8ball`: WPA-style, without called pockets.
- `9ball`.
- `uk8`: British pub rules. Two visits after a foul, a free ball on the first visit, ball in hand behind the baulk line after an in-off. Optional `game.oneVisitOnBlack`: a player on the black only ever gets one visit; `nextGame()` needs the table after the shot (its fourth argument) to apply it.
- `practice`.

The CPU (`planBot`) is a generator, so its search can be spread across frames. It simulates candidate shots with the same physics and scores the outcomes. Its strength levels are in `DIFF` (each field is explained above it); `planBot` also takes a profile object with the same fields, which is how career opponents get their personalities (`long` adds aim error on long pots).

### Career (`src/career.js`, and the career section of `game.js`)
- **The tour:** `TIERS` hold events: the pub circuit (reds & yellows, 7 ft), the club and hall circuits (8-ball, 9 ft) and the national tour (9-ball, 9 ft), three events each, every event with a `sign` for the neon sign. Each event is an 8-player knockout (you and 7 of `field`), with `races` (frames to win the quarter-final, semi-final and final) and `prize` (money for going out in each round, then for winning). Winning an event opens the next (`unlocked()`); winning the tier's last event completes the tier.
- **Opponents:** `OPPONENTS` gives each a name, a pixel portrait (`look`, drawn by `portrait()` in `game.js` from the `SPRITES` styles), a blurb, a base CPU level plus overrides (`cfg`), optional `nerves` (execution error multiplier on the final ball, see `onFinalBall()`), and a `rating` measured with `tools/sim-career.js` (Medium CPU = 1500). Ratings settle computer-v-computer matches in a draw (`simMatch()`, Elo-style, always within one game) and, through `strength()`, give the strength stars (9-ball ratings are stretched to compare with 8-ball, using the Hard CPU as the yardstick; see `GAME_SCALE`).
- **Draws and results** are seeded (`rng()`), so reloading never changes them. `enterEvent()` makes the draw (top two seeds in opposite halves), `recordMatch()` records your match, plays out the rest of the round, pays prizes and finishes the event; `withdraw()` counts as losing the current match. `validate()` checks a saved or imported career and returns a clean copy.
- **Money and the shop:** the career only counts what it has won (`earned`); the prize money itself goes into the device's locker (see Looks), by `careerPaid()` in `game.js`, with the case an event win brings. `SHOP` lists the cloths and cues sold outright (cue designs colour the shaft, joint, forearm, wrap, butt and inlay; `HOUSE_CUE` is the free one). Saves from before the locker kept `money` and `bought`; `validate()` keeps them and `game.js` moves them into the locker once.
- **In the browser:** the career lives in `CAR.data` (localStorage `retroRack.career`). Screens `cnew` (new career: name, look, aim guide fixed for the career), `career` (the hub: one tier at a time, chosen with tabs; `careerTier()` picks the one to show; its Locker button opens the locker) and `cevent` (the draw and your next opponent), drawn by `careerMenus()`; the footer's `#bCareer` and `#bWithdraw` buttons act on them. Save to file / Load from file export and import the career as JSON, with the locker inside (`locker`); loading merges it in without taking anything away.
- **Venues:** `VENUES` in `game.js` dress the room (carpet, walls, skirting, the neon sign's colours) for each tier; `setVenue(key, sign)` swaps them. A career match, and the event screen behind the menu, use the event's tier and sign; everything else uses `home`.
- **Cues:** the cue's parts take a design's colours (`applyCue()`), and a pattern drawn round the forearm (`cuePattern()`) with its effect (`cueFx()`); `cueFor(player)` decides whose cue is at the table: yours, a career opponent's own (`cue` in `OPPONENTS`), the house cue for the CPU, and online the other player's. Gloves follow the same rules (`gloveFor()`, `glove` in `OPPONENTS`; the CPU otherwise has none).

### Looks and the locker (`src/looks.js`, and the locker and gloves sections of `game.js`)
- **The catalogue:** `CASE_ITEMS` holds 60 looks that come only in the everyday cases (and see Seasons for Halloween's 30): 14 patterned cloths (`pat`, drawn by `drawPattern()` onto the bed as a texture, metre for metre), 20 cues (`pat` and `pc` for a forearm pattern, `fx` glow, neon or rainbow) and 26 gloves (`style`, one of the glove types in `STYLE` in `game.js`: sport, driver, tactical, moto, fingerless and hand wraps, plus three novelties, boxing, robot claw and skeleton; and `fx` glow, flicker or ghost). Each has a rarity (`RARITY`: common, rare, epic, legendary and mythic, with the price a duplicate sells for). The legendary and mythic ones are painted pixel by pixel from noise (`makeNoise()`, `fbm()` and `paint()`, in the collection effects section): the cloths by `clothGalaxy()`, `clothSynth()`, `clothAurora()` and `clothMagma()` (at half the bed's usual resolution, and the last four kept in `CLOTH_CACHE`, so they're quick), the cues by `cuePaint()` (`pat` holo, tubes, swirl and plasma), the gloves by `gloveTex()` (gold leaf, fire, smoke, molten crust and holographic bands, wrapped round each finger and laid across the hand; only legendary and mythic gloves have one).
- **Mythics** (red, two of each kind) move: the cloths Aurora (`anim: 'flow'`, the texture drifts, `clothFx()`) and Magma (`anim: 'pulse'`, its cracks glow through an emissive map, `clothGlow`), the cues Event horizon (`fx: 'spin'`) and Plasma (`fx: 'plasma'`), whose seamless forearm patterns scroll in `cueFx()`, and the gloves Molten and Prism (`fx: 'molten'`, `'prism'`), whose glow (Molten) or bands (Prism) move in `gloveFx()`. Brightness only changes slowly (nothing faster than about 3 times a second), and with reduced motion they hold still. `ALL` is every look by id: the shop's, the cases' and `FREE_GLOVE`. `FREE` lists what everyone owns ('house', 'none', the free glove; the five original cloths are free too).
- **Cases:** `GRADES` (bronze, silver, gold, diamond) give the odds of each rarity, the cost to open one and the price to buy one; legendaries only come in silver and better; mythics come in every grade, very rarely (0.2% in bronze up to 6% in diamond). The diamond case holds only epic or better (70% epic, 24% legendary, 6% mythic) and costs the most to open (£250) and buy (£900); its card says "Always epic or better" (`caseCard()` writes that for any grade whose odds start at epic). `roll()` picks the prize (an epic or better is guaranteed within `PITY` = 8 cases), `openCase()` pays, picks and sells a duplicate at once (but a mythic is always one not owned yet, until all six are), `reelItems()` fills the reel with items drawn from the same odds. `buyCase()` and `buyLook()` spend money.
- **Earning:** `cpuFrameWon()` (a frame won against the computer pays `CPU_PAY`, £15 on Easy up to £150 on Expert, and moves the level's meter on; `METER` = 1, so every frame won earns a case of the level's grade), `careerFrameWon()` (a case of the tier's grade for every career frame won, no pay), `eventWon()` (`EVENT_CASES` = 2 cases of the tier's grade, a championship two of the grade above, four of the best at the top) and `onlineWon()` (the day's first online win, once per local date: £100 and two gold cases). Practice and same-device games earn nothing. `frameEarn()` in `game.js` calls them when a frame ends; `EARN` holds the result for the result screen.
- **Seasons** (`SERIES`; Halloween, 1 October to 10 November): looks that come only in the season's own cases (`SEASON_ITEMS`, `series: 'halloween'`, 30 of them, two of each kind at each rarity; `SERIES_POOL`, `seriesItems()`), apart from the everyday cases and the 15 collections. `GRADE_IDS` are the everyday cases; `CASE_IDS` adds the seasons' (`trick` and `treat`, `series` on the grade; `poolOf()` gives a case's looks). Trick: earned and bought, any of its looks, duplicates sold. Treat (`fresh`): bought only, free to open, and `roll()` leaves out what you own until you own them all. `inSeason(sid, day)` says whether a local date (YYYY-MM-DD) is in it: `buyCase(l, grade, day)` refuses a season's case out of season ('season') and a Treat case once the set is complete ('complete'); `seasonWon(l, day)` gives the season's daily case for the first frame won each day (`sdaily`), called by `frameEarn()` for any frame that earns (EARN.season). Each rarity's six looks pay `SERIES.halloween.reward[r]` once (claimed `'halloween:rarity'`), all thirty `grand` (`'halloween:all'`): £5,000 and the `haunted` effect. Held season cases open at any time, and nothing is ever taken away.
- **Collections:** the case looks of one rarity and one kind make a collection (`COLLECTIONS`, keyed `'rarity:kind'`, 15 in all; `colItems()` lists one's looks): the common cloths, the mythic gloves and so on. Each pays money and cases when complete (`KIND_REWARD`: common £150 and a silver case, up to mythic £5,000 and three diamond cases). All three of a rarity make its set (`SETS`), which pays far more and adds the rarity's effect (`EFFECTS`): common £1,000, three gold cases and the chalk trail; rare £2,500, three diamond cases, gold rails; epic £5,000, five diamond cases, pot sparks; legendary £12,000, eight diamond cases, your name in neon; mythic £30,000, twelve diamond cases, the cosmic cue ball. All fifteen (`GRAND`): £50,000 and the starfield room. `claimCollections()` pays whatever is due, each only once (collections, then sets, then 'all'); `openCase()` calls it and returns what it completed as `done`, and `claimDue()` in `game.js` calls it after loading a career file and at start-up. `effects()` lists the effects earned. Dev mode's test locker counts every reward as already paid.
- **The locker** (localStorage `retroRack.locker`, `LOCK` in `game.js`): `money`, `owned`, `cases`, `meter`, `pity`, `daily`, `opened`, `claimed` (the collections paid); `validateLocker()` cleans a saved one and `mergeLocker()` brings in one from a career file. Every change goes through `lockerEdit()`, which reads the stored copy, changes it and writes it straight back, so two open pages don't undo each other's changes; a `storage` listener shows changes made in another page. A new locker starts with £40 and a silver case, so everyone can try one. On first load the locker takes in looks from older versions (`S.owned`) and a career's unspent money.
- **The locker screen** (`locker`, from the home screen's Locker card or the career hub), drawn by `renderLocker()`, with three tabs:
  - **Cases:** each grade's odds, Open and Buy, the meters and the guarantee.
  - **Inventory:** one long list (`invRow()`) of everything owned, rarest first (`lookRank()`, `lookSort()`: mythic down to common, then the shop's looks, then the free ones), under a heading per rarity; tapping one puts it in use. Above it, the collection rewards earned, each with an On/Off switch (`S.fxOff`).
  - **Halloween** (`'hw'`, shown in the season, whenever a Halloween case or look is held, and in dev mode; `seriesShown()`; on phones the tab is a pumpkin icon, so the four tabs keep to one row): the season's dates, the daily case, the Trick and Treat cards (`caseCard()`, shared with the Cases tab; Buy is dimmed out of season and says when it's on), then each rarity's six looks with its reward, rarest first, and the all-thirty reward. `seasonDates()` writes the dates out.
  - **Shop:** the looks for sale outright in a first row, then a section per rarity, rarest first: its set (how many of its three collections are done, and the set's reward), then its cloth, cue and glove collections, each with how many you have, its reward and its looks (`colTile()`: owned tiles bright with a tick, the rest dimmed); a last line for all fifteen.
  - `lookTap()` handles a tap anywhere: an owned look goes into use; one you don't own (or a shop look you don't buy) is marked to try on (`LOCKV.try`, by kind, dashed outline). The lists keep their scroll position when they redraw.
  - Item pictures are pixel art: `clothImg()`, `cueIcon()`, `gloveImg()`, `caseImg()`. Settings has a picker for each kind (`lookPicker()`).
- **The money counter** (`#bMoney`, `purse()` and `PURSE`, in the locker section of `game.js`): the locker's money with a pixel pound coin, on every menu screen, in the top-right corner beside the Settings cog. `refreshMenus()` calls `purse()`, which counts to the new amount (500 ms for a small change up to 1.4 s for a big one) with the change drifting in under it (`.moneyDelta.up`, green) or falling away (`.down`, rose). While the menu is hidden (a game, Preview, the waiting room) it leaves the shown amount alone, so money earned in a game is counted in on the way back. Opening a case sets `PURSE.hold` to what's left after paying, and `reelDone()` clears it, so the counter shows the cost at once but a duplicate's sale or a collection's reward only when the reel stops. Tapping it opens the locker (not during the reel, or from the locker). In dev mode it has a dashed border and says Test locker. With reduced motion the amount just changes. Display only.
- **Preview** (`#bPreview` in the footer of the inventory and the shop, `startPreview()`, `endPreview()`): the menu steps aside and the camera (`cam.mode` `'show'`) swings slowly round the side of the cue, lined up on the nearest ball, showing your cloth, cue and gloves with any look marked to try in its place (`PREV.looks`; `cueFor()`, `gloveFor()` and `setCloth()` use them while `PREV.on`). Nothing is saved. A tap anywhere (`#preview`), Esc or the back gesture ends it; with reduced motion the camera holds still.
- **The reel** (`#reel`, `showReel()`): the locker pays and picks the prize first, then a strip of the case's items glides past a marker and stops on it; the other items come from the case's odds and the stopping point within the prize's tile is random, so it never fakes a near miss. Each tile is in its rarity's colour (`reelTile()`), fading from a dark shade at the top to nearly the full colour at the bottom. It takes 7 seconds to stop, slowing to a long crawl. Tapping the reel skips to the end; with reduced motion there's no spin. A case that completes a collection, a set or all fifteen says so under the prize (`doneTxt()`). The reel fills most of the screen (tiles 40% of its height, at most 22% of its width) over a dim that leaves the room barely visible.
- **The Haunted Hall** (the room section of `game.js`, `HALL`): the `haunted` effect, at home only, winning over the starfield room. `dressRoom()` (called by `setVenue()` and `applyFx()`) sets the floor, walls and skirting for the venue and calls `showHall()`; `hallTex()` paints its textures once (damask, boards, cobweb, the windows' night skies, cloud, fog, the portrait, a jack-o'-lantern's carving) and `buildHall()` makes it the first time it's shown: beams along the walls with bats hanging from them, twelve ribbed jack-o'-lanterns carved on the side facing the room (their glow is an emissive map) with three orange lights, two arched windows on the far wall, cobwebs in the top corners, by the table's legs and on the lamp, three layers of floor fog, the crooked portrait on the left wall and a skeleton slumped in the far corner. Display only, on your own screen.
- **Collection effects** (the collection effects section of `game.js`): `fxOn(k)` is true when the reward is earned and not switched off; `applyFx()` puts them in place after any change. The chalk trail (`TRAIL`, an instanced mesh of dots laid every 1.2 cm along the cue ball's path, shrinking away), gold rails (`railMat` takes `goldTex()` instead of the wood), pot sparks (`sparkAt()`, from the pocket in the ball's colour; off with reduced motion), your name on the home neon sign (`signText()`: the career's name, else the online name), the cosmic cue ball (`cosmicTex()`, pale and bright, with gold spin dots) and the starfield room (`starTex()` on the walls at home). `tableFx()` moves the trail and sparks each frame. Display only, and only on your own screen: nothing is sent online.
- **The show behind the reel** (`#reelFx`, `fxStart()`, `fxFrame()`, drawn at a quarter of the screen's resolution and scaled up): faint stripes while it spins; when it stops, stripes in the prize's rarity colour and its own colour bounce round the screen, more and faster the rarer it is, with sparkles from epic, turning rays from legendary, and for a mythic shifting colours, rings, confetti, a shake and a bigger fanfare (`sfx('fanfare', tier)`). It stops when the reel closes; with reduced motion it's drawn once, still.
- **Gloves** (the gloves section of `game.js`): the one-piece hands are the owner's own procedural model, "Retro Rack hands", built in: low-poly and flat-shaded (the materials use `flatShading`; the geometry has no shared corners), one mesh per hand on a skeleton of 17 bones (`GH_BONES`: the arm, the wrist, three for each finger and three for the thumb). In the model's frame the fingers point along -z and the back of the hand faces +y; `GH_FINGERS` and `GH_THUMB` give each knuckle, width and section lengths for a right hand, and a left hand is a true mirror (`ghMake()` flips x and turns each face back round), so the poses work on both. `ghTris()` lofts rings of corners (`ghRing()`, `ghLoft()`, small boxes from `ghBlock()`) into the cuff (darker inside), the wrist and palm, four six-sided fingers and the thumb, then the type's extras from `STYLE`: a wrist strap, a back panel, a knuckle strip or a raised guard, finger pads, nails where the fingers are bare. Each triangle has a part (slot) that `ghMat()` turns into one of the glove's eight materials (`GLOVE_KEYS`: the back in the main colour, the palm side a little lighter, skin past a fingerless glove's first joint and on all of a wrap's fingers, trims toned towards the main colour by `TONE`); a textured glove's picture covers the back, palm, panel and trims alike. `ghGeo()` makes each type's mesh once per side (`HAND_GEO`, 700 to 770 triangles in four to six groups, one per material used); `ghHand()` puts one on its skeleton in a pose from `GH_POSES` (grip, bridge, and the reactions fist, thumb and open). A pose with an `anchor` says where the cue's middle line passes through the hand, and `ghAttach()` places the hand so the cue runs there: the grip on the cue's butt (a child of the cue, so it strokes with it, thumb towards the tip), and the bridge on the cloth behind the cue ball, kept flat (`level`), its anchor `restHeight` above the cloth; when the cue's line is higher than that (top spin), `updateGloves()` tips the hand up on its fingertips rather than lifting it off the cloth. The boxing glove is one faceted mitt (`boxingGeo()`, the cue resting on its thumb beside it); the robot claw and the skeleton keep their jointed parts (`partsHand()`, with `FINGER`, `THUMB` and `HAND_POSE`, in an older frame with the fingers along +x, which `handBuild()` also turns the one-piece hands into for the reactions). `gloveBuild()` makes the grip, the bridge and the reaction hand. `cheer()` plays a reaction after a shot (a thumbs-up for a pot, a shrug for a foul, a fist pump for winning the frame), off with reduced motion and during replays. A fingertip of the bridge drums while you line up. The cue hand hides when the camera is within 0.3 m of it. Display only: nothing here affects the physics.
- **Career matches** are normal CPU games: `careerPlay()` puts the menu's own choices (`M`) aside in `CAR.stash`, sets `M` from the event, and calls `startGame(false, false, resume)`, where `resume` carries the match score, who breaks and a frame in progress. `CAR.on` is true for the match: `saveM()` and Play again leave the menu's choices alone, the scoreboard and messages use the opponent's name (`botName()`), and Pause has no aim guide choice and no re-rack. `careerSave()` stores the table (`snapshot()`) after every shot, so a match resumes exactly; `careerFrameOver()` records a finished frame and, when the match is won or lost, `recordMatch()`. `careerLeave()` (from `toMenu()`) puts `M` back.

### Online play
- The browser in each seat runs the full game; the relay only forwards messages.
- **Messages sent by the relay:** `welcome` (with the seat), `peer` (on or off) and `full`.
- **Messages between players:** `hello` (name, whether a game is under way, `v` the version, and the player's `cue`, `cloth` and `glove`), `look` (a player changed their cue, cloth or gloves mid-game), `setup` (the host's rack, mode, aim guide, match length and `blackOne`, the "one visit on the black" rule), `state` (a full snapshot for resyncs), `aim` (live cue preview), `shot` (shot number, inputs, initial velocities and cue placement), `sync` (the shooter's table after the shot), `chat` (a preset index only), `concede`, `rerackOffer`, `rerackYes`, `rerackNo`, `again` and `bye`.
- **Looks:** each player's cue and gloves are shown on both screens, and the table wears the host's (seat 0's) cloth: `takeLooks()` reads them from `hello` and `look`, accepting only known design ids (anything else becomes the house cue, no gloves, or the receiver's own cloth). `NET.cloth`, `NET.peerCue` and `NET.peerGlove` are cleared on leaving. Display only: nothing here affects the physics.
- **The input-only check:** the receiver validates cue ball placement and recomputes the strike itself. The shooter's `sync` is then a cross-check; a mismatch shows a warning and adopts the shooter's table.
- **Reconnecting:** uses a per-tab client id kept in sessionStorage, so a reload keeps the seat. A duplicated tab copies sessionStorage, so each open page marks the id as in use (`rr.live`, cleared on `pagehide`); a copy that finds the mark picks a fresh id.
- **Rejoin:** whenever an online game starts, is restored or a shot ends, the page saves the room code, its client id, the opponent's name and the mode in localStorage (`retroRack.rejoin`: a list, one entry per client id, kept 3 hours). The home screen's Rejoin button (`updateRejoin()`) puts that id back into sessionStorage and joins the room, so the relay returns the same seat and an opponent whose page is still open sends the table (`state`). If neither page is still open, a fresh frame starts. Quit, Menu on the result screen, Cancel in the waiting room, a full room and the opponent's `bye` (leaving on purpose) forget the entry. Each page in a room holds a Web Lock named `retroRack.seat.<cid>` (`holdSeat()`, freed by `leaveOnline()` or by closing the page), and the button skips entries whose lock is held, so a second tab on the same device never takes over a seat that's still open.
- **Versions:** `tools/build.js` stamps `BUILD` in `game.js` with a fingerprint of the game code, shown at the bottom of the menu. `hello` carries it. Before a game starts, a mismatch (or a peer sending no version, i.e. older than this check) stops the game starting and tells the players to reload. Mid-game it only warns, since the `sync` cross-check keeps the tables matched.
- **Installable app:** `game.js` adds the manifest link and registers `sw.js` only on http(s), so a copy opened from disk stays quiet. Service workers don't run from `file://`, so test the app parts through a local web server.
- **Relay (`relay/src/index.js`):** a `Room` Durable Object per room code (seats, reconnects, listing), plus a single `Lobby` Durable Object for the open-rooms list that menus watch over a WebSocket. A single `Ideas` Durable Object keeps the players' ideas: `POST /ideas` with a plain-text JSON body (so there's no CORS preflight; the answers carry `access-control-allow-origin: *`), `op` `send` (`text`, `name`, `v`) for anyone, and `list`, `delete` (`id`) and `clear` only with `key`, the dev word, whose fingerprint must match `DEV_PRINT` (keep it the same as `DEVW.print` in `game.js`; the `ideas` browser test checks; `env.DEV_PRINT` overrides it, for the tests' stand-in word). Because anyone can post without the game, the relay does the checking: control and invisible characters taken out, line breaks made spaces, 100 characters at most, a name of 14 without `<` or `>`, `IDEA_DAY` = 5 a day from one address (kept only as a fingerprint, in `rate`, forgotten the next day), `IDEAS_DAY` = 300 a day in all, and the newest `IDEAS_KEEP` = 500 kept. Refusals answer 200 with `{ ok: false, why }` (`long`, `empty`, `limit`, `busy`, `key`, `bad`), so the game's console stays clean. Migrations are `v1` (Room), `v2` (Lobby) and `v3` (Ideas). Adding a Durable Object class needs a **new** migration tag; never edit existing ones.
- **Compatibility:** changing the message format means both players need the new version. Keep old fields working where possible.

## 4. Key decisions and why

**Delivery**
- **One self-contained `index.html`,** with fonts and three.js inlined, so the game works offline as a single downloaded file. Online play needs `config.js` next to it.
- **three.js is pinned at r159** (ES-module build, wrapped by `tools/build.js`). Upgrading is possible but not needed. If you do upgrade, re-check lighting, the `DepthTexture` outline pass and the console.

**Online play**
- **Determinism over server-side physics.** The relay never simulates. Both browsers run identical physics; the rules for that are in `AGENTS.md`. This keeps the relay tiny and free, and enables replays.
- **The trust model is aimed at friendly games:**
  - Receivers accept only shot inputs and recompute the result themselves. Cue ball placement is validated, and the strike velocities are checked.
  - The shooter's `sync` is a cross-check; on a mismatch, the receiver warns and adopts the shooter's table.
  - Known gaps: aiming aids on someone's own screen can't be detected. A modified client could stall a game by sending an illegal cue ball placement (honest clients can't do this). (A duplicated browser tab used to share the original tab's client id and fight over the seat; it now picks a fresh id.)

**Rooms**
- A listed room appears only while its creator waits, and disappears when a second player joins or the creator leaves. Nobody can join a game in progress or take a seat someone dropped out of.
- The list forgets rooms after 45 minutes waiting. Unused rooms are deleted after 6 hours.
- Rejoin is kept on the player's own device for 3 hours, well inside the 6 hours a room lasts. It uses the same seat-by-client-id reconnect as a reload, so the relay needed no change. The table itself lives only in the players' open pages, so if both close, the frame starts again.
- Chat is preset messages only (sent as an index), so there's nothing to moderate in listed rooms.

**Free tier**
- Uses the WebSocket Hibernation API, keep-alive pings answered automatically, no polling, and the open rooms list is pushed over WebSockets. Usage is far inside the free limits.

**Tooling**
- **Changes reach GitHub through Claude Code's GitHub connector.** This has been working well; keep using it. Pushing to `main` deploys to the live site, and to the relay if `relay/` changed.

**Game rules**
- **8-ball:** WPA-style but no called pockets. An illegal break (no pot and fewer than 4 balls to a rail) counts as a foul. The 8 potted on the break is re-spotted.
- **9-ball:** no push-out rule.
- **Reds & yellows:**
  - A foul gives the opponent two visits, and the first is a free ball (any ball may be hit first).
  - The two-visit advantage carries while the player keeps potting.
  - An in-off gives ball in hand behind the baulk line.
  - Potting the opponent's colour is a foul.
  - The black on the break is re-spotted, not re-racked.
  - "Lose the second visit when on the black" is an option on the setup screen ("On black: Two visits / One visit"), off by default because pubs differ.
- **Physics limitation:** the cue is always level, so there are no jump or massé shots.

**Trick shots**
- Each demo was found by searching with the real physics (`tools/find-trick-demos.js`) and checked for robustness, meaning nearby aims also work.

**Career (chosen by the owner, October 2026)**
- **A tour of tournaments,** tier by tier from the pub to a world final, rather than league seasons or a simple ladder. Each event is an 8-player knockout against named computer players, with longer matches in later rounds.
- **All three game types across the tiers:** reds & yellows in the pubs, 8-ball in clubs and halls, 9-ball at the top.
- **Rewards are looks only:** prize money will buy cloths, cues, ball sets and venue looks. No entry fees, so you can't go broke. Player "upgrades" were rejected: your skill is your real aim, and boosting it would fight the physics.
- **The aim guide is chosen when a career starts** and stays fixed for it, like a difficulty setting.
- **Opponents' strength is measured, not guessed:** `tools/sim-career.js` plays each against the Medium CPU (80 frames, accurate to about ±45 rating points). Personalities come from the CPU's own settings: accuracy, long-pot weakness, safety play, break power, and nerves on the final ball. The pub tier runs from about 1245 to 1560 (Medium is 1500), so its final boss is a little stronger than the Medium CPU; later tiers will go much higher.
- **Matches between computer players** in a draw are settled from their ratings with a seeded random number, so they're instant and never change on reloading.
- **Saving:** in the browser (localStorage) after every shot, plus Save to file / Load from file. There are no accounts or cloud saves (that would need a login and server storage). Safari can clear a site's storage after 7 days without a visit, and clearing browsing data deletes it, so the README tells players to keep a file copy.
- **Built in stages,** each playable: Stage 1 (pub tier, opponents, draws, saving), Stage 2 (more tiers and game types, venue looks, spending prize money), Stage 3 (rivals, story cards, trick-shot challenges, trophy cabinet, world final).

**Career, Stage 2 (October 2026)**
- **Difficulty aimed at the owner,** who beats the Medium CPU and loses to Hard: the national tour's best (The Metronome) measures about 70 points below the Hard CPU in 9-ball, and every tier's championship has the tier's strongest player. Yardsticks measured with `tools/sim-career.js`, Medium = 1500: Easy 1245 (8-ball) and 1309 (9-ball); Hard 1819 (8-ball) and 1728 (9-ball). 9-ball squeezes ratings together (its breaks and lucky pots matter more), so for the stars a 9-ball rating is stretched by 319/228 to compare with 8-ball. The tiers: pub 1245 to 1560, club 1420 to 1625, hall 1515 to 1705 (8-ball), national 1535 to 1655 (9-ball, 1549 to 1717 stretched).
- **Personalities can cost more than expected.** Nerves on the final ball hurt far more in 9-ball, where most frames are decided on the 9: The Metronome with nerves 1.5 measured only 1535, so his nerves are now 1.25.
- **The shop sells cloths and cues only,** so the balls always stay readable; cloth colours were chosen to keep reds, yellows and the black clear.
- **Bought looks belong to the device,** not the career: they work in every game, survive retiring, and come with a career loaded from a file.
- **Online, looks are shared:** each player's cue shows on both screens, and the table wears the host's cloth (one table, one cloth, like the host choosing the game). Unknown ids from the other side fall back to the defaults.
- **A room per tier:** carpet, walls, skirting and the neon sign (with the event's name) change; the table and lighting don't.

**Settings and graphics (October 2026)**
- **The sharpest picture is the default** (pixel size 1×, full colours), as the owner chose, and it was applied once to everyone already playing (`S.gfx`), since saved settings would otherwise keep the old 3× and 8 shades. It costs more on phones and softens the pixel-art look; anyone can pick a bigger pixel size in Settings.
- **Pixel size Max, not a literal 0.5×** (the owner asked for finer aim lines). 1× already uses every pixel of a screen at 100%, so finer than that only helps where the screen has more pixels than the page: Windows scaled to 125% or more, and phones. Max matches the screen exactly (one game pixel per screen pixel). A literal 0.5× was tried: it matched Max at 200%, was a little softer at 150%, and at 100% the browser shrank it, leaving the 1-pixel aim line thin, faint and dotted. Max costs more drawing in proportion (2.25 times the pixels at 150%), so it isn't the default.
- **Settings is a big panel** in four sections, two columns on computers, with bigger buttons; it fits a 1280×720 screen without scrolling. A click outside it closes it.
- **The browser tests draw in software,** so the sharper default made them slower.

## 5. Reference numbers

**Tables** (playing area, ball size)
- **US 9 ft:** 2.54 × 1.27 m, balls 57.15 mm and 170 g. Pocket mouths: corners 116 mm, sides 132 mm. Jaw angles 38° and 76°. Head string at a quarter of the length.
- **UK 7 ft:** 1.83 × 0.915 m, balls 50.8 mm and 140 g. Pocket mouths: corners 89 mm, sides 97 mm. Jaw angles 52° and 80°, rounded with fillets of 30 mm (corners) and 24 mm (sides). Baulk line at a fifth of the length.

**Physics**

| Quantity | Value |
|---|---|
| Sliding friction | 0.2 |
| Rolling resistance | 0.010 |
| Spin decay | 10.9 rad/s² |
| Ball–ball restitution | 0.95, with speed-dependent friction (this produces throw) |
| Cushion restitution | 0.88 − 0.035 × normal speed, minimum 0.62 |
| Cushion friction | 0.2 |
| Cushion nose height | 0.27 R above the ball's centre |
| Cue mass | 0.54 kg |
| Tip restitution | 0.8 |
| Maximum tip offset | 0.5 R (the miscue limit) |
| Squirt | about 1.3° at full side spin |
| Time step | 1 ms |

**Power:** cue speed = 0.08 + 6.5 × power^1.7 m/s. Full power sends the ball off at about 9 m/s.

**Lighting**, in physical units, equal to the old legacy values × π:

| Light | Intensity |
|---|---|
| Hemisphere | 0.32π |
| Sun | 0.22π |
| Camera fill | 0.2π |
| Two point lights | 0.51π each, distance 6, decay 0.43 (fitted to the old falloff) |

## 6. How things are tested

- **Career rules:** `tests/career.test.js` (24 tests): tour data, tiers, draws, results and money, saving and loading (including saves from before the locker), and the opponents' CPU settings.
- **Looks:** `tests/looks.test.js` (32 tests): the catalogue, case odds over many openings, diamond cases only ever epic or better, the guarantee, mythics, collections and their rewards, no duplicate mythics, opening, buying, duplicates, earning, the saved locker, and career opponents' gloves.
- **Physics and rules:** `tests/physics.test.js` (27 tests). These cover bit-identical determinism, pockets on both tables, breaks, the rules for every mode, the trick demos, and that the context packs are up to date.
- **The browser:** headless Chromium (Playwright) with software WebGL (SwiftShader). The page exposes `window.__rr` (state, world, game, aim, NET, beginStroke and so on) to make scripting easy. The browser tests have lived in `tests/browser/` since 7 October 2026; `node tests/browser/run-all.js` runs them all (see `AGENTS.md`, Testing).
- **Online:** the real Cloudflare runtime runs locally (`npx wrangler dev`), and the game is opened with `?relay=ws://127.0.0.1:8787` in **separate browser contexts**, so each gets its own client id. After every shot, the ball positions and the `game` objects of both clients are compared, and they must be identical. Covered: reload rejoin, Rejoin from the home screen, a full room, rematch, re-rack and concede, chat, replaying while the opponent shoots, duplicated tabs, and version mismatches. The ideas players send go to the same local relay, read with a stand-in dev word (`ideas` test).
- **Software WebGL is slow,** so keep test windows small (about 480×360) unless the size is what's being tested.

## 8. How changes are made

- Work happens in Claude Code, which pushes to GitHub through its GitHub connector. That is set up and working.

- **Keep it to one change at a time.** Test online changes with the local relay before merging, since both players need the same version.

# Retro Rack

3D pixel pool you can play against the computer, on one device, or online against a friend.

## What's in this folder

| File | What it is |
|---|---|
| `index.html` | The game. It works on its own for offline play. |
| `config.js` | One setting: your relay address, so online play knows where to connect. |
| `sw.js`, `manifest.webmanifest`, `icons/` | Let people install the game as an app and play it offline. |
| `relay/` | A tiny Cloudflare Worker that passes messages between the two players, and keeps the ideas players send. |
| `src/`, `vendor/`, `tools/`, `tests/` | The source code, the 3D engine and fonts, the build tool and the tests. `index.html` is built from these. |
| `AGENTS.md`, `CLAUDE.md`, `HANDOVER.md` | Notes for AI assistants and developers: how the project fits together and how to change it (`CLAUDE.md` points Claude Code to `AGENTS.md`), and its history and decisions. |
| `CONTEXT.md`, `CONTEXT-SHORT.md` | The whole project in one file, for an AI that can't open this repository (see "Asking another AI about the project" below). Made by the build; don't edit them. |

Everything here runs on free plans. You need a GitHub account and a Cloudflare account, and everything is done in your web browser.

## Step 1: Put the game on GitHub Pages

1. Sign in to github.com and open https://github.com/flopp-r/retro-rack.
2. Click **Fork** (top right), keep the name `retro-rack`, and click **Create fork**. You now have your own copy.
   (GitHub Pages is free for public repositories, so anyone can see the code. That's fine; there's nothing private in it.)
3. Go to the repository's **Settings**, then **Pages** in the left sidebar. Under **Build and deployment**, set **Source** to **Deploy from a branch**, choose the **main** branch and the **/ (root)** folder, then click **Save**.
4. Wait a minute or two and refresh the page. It will show your site address, something like `https://yourname.github.io/retro-rack/`. Open it and the game should load. Offline modes work already.

## Step 2: Put the relay on Cloudflare

1. In the Cloudflare dashboard, open **Workers & Pages** (it may be under **Compute** in the sidebar) and click **Create**.
2. Choose **Import a repository** and click **Get started**. Connect your GitHub account when asked, and give Cloudflare access to the `retro-rack` repository.
3. Pick the `retro-rack` repository.
4. Set the project name to exactly `retro-rack-relay`. It must match the name in `relay/wrangler.jsonc`.
5. Open the advanced or build settings and set the **Root directory** (sometimes called **Path**) to `relay`. Leave the build command empty, and leave the deploy command as `npx wrangler deploy`.
6. Click **Save and Deploy** and wait for the build to finish, which takes a minute or two.
7. Open the new Worker. Its address looks like `https://retro-rack-relay.yourname.workers.dev`. Visit that address in your browser; it should say **Retro Rack relay is running.**

Cloudflare occasionally renames buttons. If something doesn't match exactly, look for the closest option with the same meaning.

## Step 3: Connect the game to the relay

1. On GitHub, open `config.js` in your repository and click the **pencil** icon to edit it.
2. Paste your relay address between the quotes on the last line, so it looks like this:

   ```js
   window.RETRO_RACK_RELAY = "https://retro-rack-relay.yourname.workers.dev";
   ```

3. Click **Commit changes**. GitHub Pages updates within a minute or two.

That's it.

## Playing online

1. Open your game address, choose **Multiplayer**, then **Online**, and type your name.
2. To join a friend, pick their room from **Open rooms** and click **Join**, or type their code into **Join with code**.
3. To host, click **Create a room**, choose the game, pick **Listed** or **Private**, then click **Create room**. You get a five-character room code and an invite link.
   - **Listed** rooms appear in Open rooms for anyone who opens your game page, until a second player joins.
   - **Private** rooms never appear in the list; they can only be joined with the code or link.

The player who creates the room chooses the game and the aim guide, and those settings apply to both players. You see your friend's cue move as they aim, in their own cue design and gloves; the table uses the host's cloth. Your first online win each day pays £100 and two gold cases. If either connection drops, the game waits and puts you both back on the same table when you reconnect, including after reloading the page. If you close the game by accident (the app swiped away, the tab shut, a flat battery), the home screen shows **Rejoin** (for example "Rejoin 8-ball with Sam") for three hours; it puts you back in your seat, and on the same table if your friend's game is still open. Quitting on purpose forgets it. A room leaves the list as soon as someone joins it, or if its creator leaves first, so nobody can wander into a game already in progress. Rooms tidy themselves away after six hours unused.

**Fair play.** Your game only accepts your friend's shot *inputs* (aim, power, spin and cue ball placement), then works out what happens itself. An edited copy of the game can't report fake results or place the cue ball illegally without your game noticing. It can't stop someone using an aiming aid on their own screen, though, so this is for friendly games.

**Cost.** Cloudflare's free plan covers this comfortably. If the daily free allowance were ever used up, online play would simply stop working until the allowance resets at midnight UTC. You can't be charged unless you upgrade the plan yourself.


## Installing it as an app

Open your game address, then:

- **Edge or Chrome on a computer:** click the **App available** (install) icon at the right of the address bar, then **Install**.
- **Android:** open the browser menu (**⋮**) and choose **Install app** or **Add to Home screen**.
- **iPhone or iPad:** in Safari, tap **Share**, then **Add to Home Screen**.

The app opens in its own window. Once installed and opened once, it starts without internet for games against the computer, on one device, and practice. Online play still needs a connection.

## Features worth knowing

- **Career:** in **Single player**, **Career** starts a tour of knockout tournaments: the pub circuit (reds & yellows on the 7 ft table), then the club and hall circuits (8-ball) and the national tour (9-ball), on the 9 ft table. Pick a name, a look and an aim guide (fixed for the whole career), then enter events, play your way through the draw against named computer players, and win prize money, cases and trophies. Winning an event opens the next, and winning a circuit's championship opens the next circuit. Each circuit has its own room. The career is saved after every shot, so you can leave a match and carry on later. It is stored in this browser on this device: **Save to file** keeps a copy, with your locker (or moves both to another device with **Load from file**), and clearing your browser's data would delete them.
- **Locker:** on the home screen (and the career's hub). It holds your money, your cases and every cloth, cue and pair of gloves. Some are sold outright; the rest come in **cases**, in four grades (bronze, silver, gold and diamond) with their odds shown on each. A diamond case is always epic or better, but costs the most to open (£250). Opening a case costs money: the room goes dark, a big reel of the case's items spins to a stop on your prize, and the background lights up in its colours, more wildly the rarer it is. The rarest, **mythic** (red), can come in any case but very rarely; the six mythic looks move (a drifting aurora cloth, a glowing magma cloth, two cues with moving patterns and two gloves that change colour). Gloves are low-poly hands that grip the cue, make the bridge and react after a shot. An epic or better is guaranteed within every 8 cases, and anything you already own is sold for you. You earn money and cases by winning frames against the computer (every frame won pays £15 on Easy up to £150 on Expert, and gives a case of that level's grade: bronze on Easy up to diamond on Expert), playing the career (prize money, two cases for every event won, and a case of the circuit's grade for every frame won), and with your first online win each day (£100 and two gold cases). Practice and same-device games earn nothing. Looks work in every game, stay if you retire a career, and online your opponent sees your cue and gloves. **Gloves** hold the cue and make the bridge on the cloth, and give a thumbs-up when you pot, a shrug when you foul and a fist pump when you win the frame. The locker has three tabs: **Cases**; **Inventory**, one long list of everything you own, rarest first; and **Shop**, with the looks for sale and each rarity's collections. There are fifteen **collections**: the cloths, the cues and the gloves of each rarity. Complete one for money and cases; complete all three of a rarity (its **set**) for a much bigger prize and an effect only a set gives: a chalk trail behind the cue ball (common), gold rails (rare), sparks when a ball drops (epic), your name in neon (legendary) and a cosmic cue ball (mythic). All fifteen bring £50,000 and open the room onto a starfield. Each effect can be switched off in the inventory, and only you see them. A mythic is never a duplicate until you own all six. Choose looks in the locker, or in **Settings** (the cog, top right in the menus). Your money is shown beside the cog on every menu screen, counting up or down when it changes; tap it to open the locker. **Preview**, in the locker, shows your cloth, cue and gloves at the table; tap a look you don't own first to try it on. The reel's tiles are in their rarity's colour: grey common, blue rare, purple epic, gold legendary, red mythic.
- **Halloween (1 October to 10 November):** the locker gets a Halloween tab with two cases of their own, holding 30 Halloween looks you can't get anywhere else (two cloths, two cues and two pairs of gloves at each rarity). Your first frame won each day in the season (against the computer, in the career or online) earns a **Trick case**: any Halloween look, duplicates sold as usual. A **Treat case** is bought, and always gives a look you don't have yet, so 30 of them finish the set. Each rarity's six looks pay money and cases, and all 30 turn the room at home into the **Haunted Hall**: jack-o'-lanterns, bats, cobwebs, moonlit windows, fog, a portrait whose eyes follow the cue ball, a skeleton in the corner and a Haunted Hall sign (switch it off in the Inventory). Out of the season the cases can't be bought or earned, but ones you have still open, and everything stays yours.
- **Replay:** press **V** or the **Replay** button to watch the last shot again. Use slow motion and orbit the camera while it plays.
- **Menus:** **Single player** leads to games against the computer and to practice; **Multiplayer** to online and same-device games. Back (or Esc, or a phone's back gesture) returns a screen. **Play again** on the home screen starts your last setup in one tap.
- **Matches:** on a game's setup screen, under **Match**, choose first to 3, 5 or 7 racks, for CPU, same-device and online games.
- **Concede or re-rack:** both are in the **Pause** menu. Online, a re-rack is offered to your opponent, who can accept or decline.
- **Quick chat:** in online games, the **Chat** button sends a short preset message.
- **Ideas:** the lightbulb beside the cog in the menus sends the game's maker an idea of up to 100 characters, with your online name if you've set one. Up to five a day.
- **Trick shots:** in **Practice**, choose the **Trick shots** rack. **Show me** plays a demo. **Edit table** lets you drag balls into your own layout and shows **Add balls**, which puts more on the table (or takes them off). **Save layout** adds it to the list.
- **Reds & yellows, "On black":** on the setup screen, choose whether a player on the black gets two visits after a foul or only one (a common pub rule). Online, the host's choice applies to both players.
- **Shot camera:** when you press Shoot, your aim is held for a moment while the view glides in to stand over the cue; then the cue strikes, and a moment later the view rises high above the side of the table so you can watch every ball, with the buttons faded out of the way (if you shot from the Overhead view, it rises back to that). It goes back to your view once the balls stop. Turn it off under **Pause**, **Shot camera**.
- **Markers:** a pulsing gold halo shows the balls you're on once you have a colour (in 9-ball, the lowest ball). Turn it off under **Pause**, **Markers**.
- **Settings:** the cog (top right in the menus, Pause in a game) opens a big panel: aim guide and markers, looks, display (pixel size and colours; 1× and full colours are the default, Max uses every pixel a scaled screen or phone has for the finest lines, and a bigger pixel size is more retro and easier on phones) and sound. Click anywhere outside it to close it.
- **Sound and fullscreen:** **Settings** sets the volume (Off to 100%). The **Fullscreen** button, in the menu and in game, hides the browser's bars where the browser allows it (not on iPhone, where installing the app does the same job).
- **Phones:** held upright, the game suggests turning sideways (tap OK to stop the hint). On Android, your pots give a short buzz and fouls a longer one; switch it off under **Vibration**.
- **Fine aim:** the **<** and **>** buttons either side of the aim readout turn by 0.05° per tap; held, they start turning slowly and speed up. For finer still, slide a finger (or the mouse) along the aim readout: 4 screen pixels turn 0.01°. On a keyboard, **Ctrl** with **←** or **→** turns 0.01°.
- **Fine power:** the readout under the power bar shows the cue ball's speed to 0.01 m/s. On a keyboard, **Ctrl** with **↑** or **↓** changes it by exactly 0.01 m/s per press (on a gentle shot, about 2 to 3 cm more or less roll); holding the keys does nothing more. On a touch screen, slide along that readout: 4 screen pixels change it by 0.01 m/s, right for more.
- **Follow next shot:** after a shot, when it's your turn again and you're using the free view, the camera glides to just behind the cue ball, looking at the ball it's pointing at (the nearest one you're on), with both on screen. It happens on your turns only, not while the computer or an online opponent is shooting. Switch it off in Settings (Follow next shot) for a view that stays where you put it. Cue view always follows the cue ball, and the overhead view shows the whole table.
- **Phone buttons:** on a phone the game's buttons are small squares with pictures (Shoot keeps its word). Press and hold one to see its name.
- **Spin diagram:** the small ball beside the power bar shows where the tip will strike; tap it to show or hide the big spin diagram. It starts hidden on a phone and shown on a computer, and remembers your choice.
- **Controls panel:** the keys listed in it can be tapped, and do what the key does: handy on a phone for things like **O** (centre the spin) and **F** (reset the view). The views, Shoot and the practice keys close the panel; aim, power and spin keys leave it open for more taps.

## If something isn't working

- **Stuck on "Connecting…" or "Reconnecting to the relay…":** check the address in `config.js`. It should start with `https://` and end with `workers.dev`, with nothing else inside the quotes. Visit the address directly to confirm it says the relay is running.
- **Cloudflare build fails mentioning the name:** make sure the Worker is called `retro-rack-relay`, or change `"name"` in `relay/wrangler.jsonc` to match your Worker's name.
- **GitHub Pages shows a 404:** give it a few more minutes, and make sure `index.html` sits at the top level of the repository, not inside another folder.
- **"That room already has two players in it":** someone else is in that room. Create a new one.
- **"…different versions of Retro Rack" or "…an older version":** online players must have the same version. Reload (Ctrl+F5 on a computer, or close and reopen the app on a phone), then come back to the room. The version is shown at the bottom of the menu, so you can compare.
